# Dashboard Work Activity and Today filter — 2026-10-20

The desktop dashboard and the existing phone employee/manager home now include the same Work Activity workspace. It reuses Chart.js, authentication, company/location/department/own-record scope checks, the JSON store and existing task detail routes. No packages or database collections were added.

## Using the dashboard

- The header offers Today, Last 7 days, Last 30 days and Custom range. Today is the initial default. The last selected range and timezone are saved separately for each account on the current device.
- The default timezone is the linked employee company's configured attendance timezone, then the account's first assigned company, then the configured business default (`STOCRANT_TIME_ZONE`, otherwise Asia/Qatar). The searchable timezone selector lets the user save a dashboard preference without changing company attendance/payroll settings. The resolved zone and exact dates are visible below the header.
- Today and one-day custom selections use 24 local-clock hourly buckets; longer periods use daily buckets. Both bounds are inclusive calendar dates. Daylight-saving fall-back hours share their local-hour bucket; spring-forward hours have zero records. Presets include the current day and refresh across midnight while the screen is open.
- The cyan filled line counts completed tasks; the dashed blue line counts recorded work updates. Legends, integer axes, exact-date/timezone tooltips, responsive sizing and reduced-motion support apply in both themes and languages. The data table provides keyboard-accessible drill-down for each point.
- Click a point or its table Open button to view that bucket's paginated records and existing task-detail links. Recent work activity follows the same selected period. The completion and update KPI totals use the same aggregation as the chart and records.
- Outstanding and overdue cards are current backlog snapshots across all creation dates. Attendance, shifts, pending approvals, stock and finance balances retain their existing live/snapshot meanings. The header selection also updates the existing Workspace insights date filters and dated audit activity. Its advanced analytics controls remain independently usable; workforce/company distributions remain current snapshots.

## Source records and permissions

`GET /api/workspace/dashboard-activity` accepts `range=today|7|30|custom`, optional inclusive `start`/`end`, validated IANA `timezone`, and optional `bucket`/`page` for drill-down. Custom periods are limited to one year; records paginate at 20 rows. Authentication and the normal password-change gate apply. Task access requires Operations-view permission. The backend filters current tasks through existing tenant, company, location, department/section and own-record rules before joining their history. Employees without this permission see a clear unavailable state and no task data; granting an existing own-record role Operations-view permits only its scoped assignments.

Activity comes from stored `workActivity.occurredAt` timestamps, not task creation dates or fabricated series. Missing or invalid timestamps are excluded. Every new task mutation now stores an additive `completionTransition` boolean and optional `previousStatus` on its automatically authored activity. Only an actual transition into Completed contributes a completion. Repeated comments/edits on an already-completed task do not add completions. A task completed multiple times contributes once per selected period, in its first qualifying bucket, so daily/hourly sums equal the unique-task KPI. The task activity endpoint now writes one history entry per update instead of the previous automatic-entry-plus-comment duplication.

Legacy records use observed sequential status transitions (and an explicit recorded creation in Completed status) where available. A first observed Completed snapshot without prior status evidence does not invent a completion date. Historical duplicates and business records are preserved. Deleted/unreadable tasks are excluded with their history; no new access to deleted or out-of-scope records is granted. Work updates describe the stored activity records, which can include historical duplicate entries retained from earlier versions.

No permanent task/status/history backfill runs. Existing identifiers, account links, business data, status workflows and payroll remain unchanged. Direct authored activity cannot set the protected completion-transition flag; it is derived from actual task mutations. The endpoint reads the existing in-memory store, scans scoped history once per request and uses a task map for joins. The UI debounces date edits, ignores stale responses and uses one activity-summary request per committed selection; point records load only on demand.
